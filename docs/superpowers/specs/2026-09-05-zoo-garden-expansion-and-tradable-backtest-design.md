# 动植物园扩容与可交易回测设计

## 目标

扩充植物园的明确多字词覆盖，统一网站的动物园与植物园文案，并在不改变现有理论指数历史口径的前提下增加可交易回测层。

## 设计

植物园继续使用 `plant_rules.yml` 的严格词与扩展词两层结构。本次用户提出的多字组合全部加入扩展词，不启用单字「松、杉、柏、艾、柳」等词，从而扩大覆盖但控制误匹配。页面总标题和调仓页说明同时明确两个主题，调仓数据继续分别读取动物园和植物园快照。

回测保留当前 `zoo_strict_ret` 与 `zoo_extended_ret` 作为理论毛收益。新增独立的交易会计层，使用前一日权重按价格漂移后的调仓前权重，与再平衡目标权重比较，计算换手、佣金、卖出印花税和滑点。成本默认关闭，成本后结果写入附加字段，不覆盖既有主指数字段。

异常成分的规则判定仍在当前交易日完成，但交易会计层把异常移除视为下一可执行交易日的目标变更，避免把收盘后才能知道的信息当作当日可成交交易。停牌和涨跌停无法执行的交易保留为未完成交易并延续到下一日。

## 输出与兼容性

现有公开 JSON 和网页主图字段保持兼容。NAV CSV 增加成本后收益、成本后净值、换手和交易成本字段。交易成本配置使用独立的 `backtest.yml`，默认值为零，避免规则词表更新或新版本部署时静默改变理论指数。

## 验收标准

1. 用户列出的植物公司简称都能命中扩展植物园，原有排除案例仍不命中。
2. 页面标题和调仓页文案不再暗示只有动物园，调仓页同时显示两个主题。
3. 理论指数旧字段数值口径不变。
4. 交易会计单元测试覆盖价格漂移换手、成本计算、停牌/涨跌停延迟和异常次日执行。
5. Python 测试、前端测试和生产构建通过。
